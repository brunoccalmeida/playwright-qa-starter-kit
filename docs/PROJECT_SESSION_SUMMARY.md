## Armadilhas do ambiente

Vistas em missões anteriores; nenhum portão as pega.

- **Windows:** no Git Bash, `python` é o atalho da Microsoft Store e trava esperando interação (o projeto não usa Python). O PowerShell 5.1 corrompe as aspas de um `--jq` passado ao `gh`: use o Bash. O Node instalado via winget só entra no `PATH` de processos abertos depois (reinicie o VS Code).
- **Flaky em app de terceiros:** antes de esperar a falha voltar, procure no código do upstream um dado que force a causa no ambiente real (na #54, o tamanho da coluna de e-mail do serviço de mensagens). Isso é a injeção do passo 3 da política, e dispensa subir o app.
- **Invalidar um token numa sonda:** o logout da UI API não invalida nada (KI-3); use o do serviço, `POST /api/auth/logout` com `{token}`, e confirme com `POST /ui-api/auth/validate` (`403`). Fixture de teste desmonta na ordem inversa da montagem: uma sonda no teardown de uma fixture pode rodar antes da limpeza de outra e derrubá-la (na #70, deixou 6 quartos no ambiente). Num teste, invalide um login próprio: o `adminToken` é o da limpeza do quarto, que leria o `403` como reset do ambiente (#80).
- **Sondas:** confira o diff da mutação antes de ler o resultado (um `sed` por intervalo já mutou o título em vez da asserção, e o teste "passou"). Mutação só vale depois de uma linha de base verde. `git revert` desfaz o commit inteiro, inclusive outra sonda, e não aceita `-q`: confira `git diff main --stat` depois de desfazer. Faça a sabotagem que sobrescreve um método (ex.: `RoomApi.delete`) disparar só na primeira chamada: na #75 ela disparou em todas, invalidou também o token do login novo, e o caso "recuperado" pareceu quebrado.
- **Segredos na evidência:** cite o formato de um segredo, nunca o valor. No CI, o relatório embute o diff do PR (`captureGitInfo`), e um token copiado para um documento como evidência já foi parar no relatório. Um token literal num spec aparece no `snippet` do relatório: monte o valor em tempo de execução.
- **Flaky no CI:** `gh run view --log-failed` e a lista de runs falhos não veem tentativas que terminaram verdes; percorra `actions/runs/{id}/attempts/{n}/jobs`.
- **Script de sonda fora do repositório** (scratchpad): importe o `playwright-core` do projeto por URL `file:///` (ESM ignora `NODE_PATH`).
- **Falha só no CI:** reproduza na imagem oficial (`mcr.microsoft.com/playwright:v<versão>-noble`, `--ipc=host`, `CI=true`), com o código copiado por `git ls-files | tar` e `npm ci` dentro do container.
- **Travas do agente:** o Claude Code recarrega o `settings.json` com atraso; depois de mudar uma regra, repita a sonda antes de concluir que ela não funciona. Bloqueio pelo motivo errado não prova a regra: uma sonda de controle separa as hipóteses.

## Decisões vigentes sem outro registro

- **Comportamento sem requisito escrito é achado, não KI:** a home mostra só os 3 primeiros quartos; reserva no passado e sem e-mail é aceita; criar quarto com o formulário vazio dá 400 sem mensagem na tela. Nenhum ganha `test.fail()`, porque um teste que afirma uma regra inventada não prova nada.
- **zizmor na persona `regular`:** a `auditor` aponta `secrets-outside-env` nas credenciais de teste. São as credenciais públicas do app de demonstração, e um GitHub Environment só para elas seria cerimônia; para cliente com credencial real, reavaliar.
- **KI-3 nas propostas comerciais:** entra como exemplo de método (achar o bug, prová-lo com um `test.fail()` que afirma o comportamento correto, documentar o impacto), não como vulnerabilidade inédita: o Restful Booker Platform é um app de treino com bugs conhecidos.
